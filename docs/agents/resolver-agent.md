# ⚖️ Resolver Agent

## 1. Identity
- **Registry name:** `resolver`
- **Purpose:** The judge. It ends the debate by reconciling any remaining conflicts using a
  fixed priority order and synthesizing the **single final `HealthPlan`** — including the
  "what each agent changed and why" narrative that is the demo's payoff.
- **Model tier:** strong (synthesis + trade-off reasoning).

## 2. Why this agent exists
Someone has to *decide*. The Critic finds conflicts but deliberately doesn't resolve them;
the specialists each advocate for their slice. The Resolver applies the project's
conflict-resolution priority (safety > physiology > budget > preference) to produce one coherent
plan, and — critically for the RFP — explains how each agent's output influenced the final
decision. Keeping "decide" separate from "find problems" makes both the Critic and the Resolver
clean and the trace easy to narrate.

## 3. Inputs
- The full final `PlanState`: `constraints`, `nutrition`, `fitness`, `budget`,
  `open_conflicts` (any that survived the refinement rounds), `messages`, `round`.

## 4. Outputs
- **`HealthPlan`** ([data-models.md](../data-models.md) §8): the integrated diet + workout +
  budget, a headline `summary`, a `rationale`, `resolved_conflicts` (what was reconciled and
  how), `open_tradeoffs` (anything unresolved after `MAX_REFINEMENT_ROUNDS`),
  `agent_contributions` (per-agent "what it decided / what changed it"), `requires_professional`,
  and `disclaimers`.
- Emits `RUN_COMPLETED` with the `HealthPlan` in the payload (terminal trace event).

## 5. Tools
- None. It synthesizes from state.

## 6. Behavior / algorithm
1. If `constraints.requires_professional` (red flag): **do not optimize**. Produce a plan whose
   primary recommendation is to consult the relevant professional first, include only safe
   general guidance, and set `requires_professional=True`. (Safety overrides everything.)
2. Otherwise, for each remaining `Conflict`, apply the priority order from
   [orchestration.md](../orchestration.md) §6:
   1. Medical safety (never violate),
   2. Energy/physiological soundness (safe, effective),
   3. Budget feasibility (fit budget without breaking 1–2; if impossible, present min-feasible
      cost + the gap),
   4. User preference & adherence.
   Record *which rule* decided each trade-off in `resolved_conflicts`.
3. Assemble the integrated `HealthPlan` from the latest specialist outputs.
4. Write `agent_contributions`: for each agent, a 1–2 line summary of what it decided and which
   other agents/conflicts changed its output (e.g. "Nutrition: 2100 kcal high-protein veg plan;
   swapped paneer→tofu+legumes after Budget's revision request; capped added sugar per Medical
   Risk").
5. Attach all `required_disclaimers`. Set `generated_at`.

## 7. Prompt design
- **System prompt intent:** "You are the final decision-maker. Reconcile the remaining conflicts
  using the strict priority: medical safety first, then physiological soundness, then budget,
  then preference. Produce one coherent plan and clearly explain how each agent's work shaped
  it. Be honest about any trade-off you couldn't fully resolve. If a professional referral is
  required, lead with that and do not optimize around a serious medical risk."
- **Structured output:** returns `HealthPlan`.

## 8. Interdependencies
- **Influenced by:** every agent (it reads the whole state) — especially Medical Risk (hard
  overrides) and Critic (the conflicts to resolve).
- **Influences:** the user (final output). It is the terminal node.

## 9. What is lost if removed
There's no final, coherent recommendation — just a pile of possibly-conflicting specialist
outputs and a list of unresolved conflicts. You lose the mandated "final
recommendation/decision generated by the system," the principled trade-off resolution, and the
"what each agent changed" narrative that makes the collaboration legible in the demo.

## 10. Extension ideas
- Produce 2–3 plan variants (e.g. "strict budget" vs "best results") and let the user choose.
- Generate a printable/exportable plan (PDF) and a week-by-week calendar.
- Feed acceptance/feedback back in for a second optimization pass.
